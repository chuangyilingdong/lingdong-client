### 平台契约端到端已验证（2026-09-23，新增 `scripts/p122-platform-contract.mjs`）

跑法：平台仓库 `node scripts/dev-bench.mjs`（临时库 + 5 个 VIBECODING 课堂 + local-mock 模型），
然后客户端仓库 `node scripts/p122-platform-contract.mjs`。它逐条重放 `platform-gate.ts` 的真实调用：

```text
✓ ① 登录 POST /api/auth/login                              → 小明
✓ ② GET /api/student/runtime/client-context                → classroom / gateway.key / sends / presets
✓ ③ 网关 POST <gateway.baseUrl>/chat/completions           → OpenAI 兼容回复（local-mock）
✓ ④ 发送次数单调推到 N+1                                    → 1 → 2
✓ ⑤ GET /api/student/works                                 → 列表
✓ ⑥ POST /api/student/runtime/submit-upload（JSON）          → 交作品成功
✓ ⑦ 新作品出现在 /api/student/works
✓ ⑧ POST /api/auth/logout
pass: true, checks: 8
```

跑这条时踩出的三条**平台侧**事实，值得同步给平台项目（客户端侧不用改）：

1. **`vibecoding_sends` 不是「请求次数」**，而是「请求体里 user 消息条数的单调最大值」
   （平台 `vibecodingLessonSettings.js` 注释写明：防学生靠压缩历史刷新额度）。
   所以"发一条消息 → 恰好 +1"只对**第一次**成立；第 N+1 次要带上 N+1 条 user 消息。
   验收脚本按"次数"写会得到假失败。
2. **平台响应统一信封是 `{ success, ok, data }`**，客户端 `call()` 里有 `payload?.data ?? payload`。
   任何新的客户端侧探针/脚本都要照抄这一步，否则会把"登录成功"误判成"没有 token"。
3. **`dev-bench.mjs` 的课堂夹具已过期**：它只改 `class_sessions.delivery_mode`，
   而门禁判据已改成读**课时**的 `course_lessons.delivery_modes`（多选）。
   结果是验证台开出来的课，客户端进去一律 `CLASSROOM_MODE_MISMATCH`（"当前是画布课堂…"）。
   夹具应按课时写入 `delivery_modes`（含 VIBECODING）才能用于联调。
4. **`dev-bench` 的 local-mock 还缺 TEXT 渠道模型清单**：fresh 库里 `platform_settings.ai_provider_policy` 是空的，`client-context.models=[]`。客户端会走内置兜底；`p122` 允许空清单，但要验平台别名真正下发，需在临时库补 `modalityChannels.TEXT + channels[].models/modelMappings`。

`node scripts/p123-install-cycle.mjs <安装包路径>` → **8/8 通过**：

```text
✓ ① 全新安装：主程序 + 卸载器落地
✓ ① 注册表：DisplayVersion=0.1.7-alpha.2.1，且 **InstallLocation 已写入**（0.1.6 那条是空的，本版改进）
✓ ② 覆盖升级：再装一次，版本不变、文件被替换、**用户数据保留**
✓ ③ 静默卸载：安装目录与两个注册表项都清掉
✓ ③ 卸载默认保留本机数据（我们新加的询问 + /SD IDNO 生效）
✓ ④ 还原测试机原有安装的注册表（按测试前原值比对，不再假定版本）
```

⚠️ 两个只有跑过才知道的坑（脚本里已处理）——

1. **NSIS 卸载器是异步的**：它把自己复制成临时 exe 后再异步收尾，`execFile` 返回 ≠ 卸载完成。
   不等到进程真正退出就判定（或就还原注册表备份），备份会被它**随后**删掉。
   同一个道理对用户也成立：卸载后立刻重装，可能撞上前一次收尾。
2. **有两个注册表键**，少管一个就会误触发「发现旧安装 → 先静默卸载」：
   `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\<guid>`（应用和功能那条）与
   `HKCU\Software\<guid>`（electron-builder 判断「装没装过」用的，存 InstallLocation）。
   本机测试脚本为了不碰用户正在用的 `E:\vibe` 安装，是**先导出并临时移除这两个键**，跑完再还原。

### ⚠️ 事故与修复：gate 没进包 → 装完一启动就 ERR_FILE_NOT_FOUND（2026-09-24）

现象：安装 0.1.7-alpha.2.1 后启动报
`Desktop page failed to load: file:///<安装目录>/resources/gate/loading.html (-6: ERR_FILE_NOT_FOUND)`。
即 `resources/gate/` **整个目录没被打进包**（登录页/等待页/课堂选择页都在里面）。

根因（不在打包流程，而在补丁脚本自身）：`apply-client-gate.mjs` 的 `patch()` 用来判断「是否已打过」的
默认标记取的是 **replacement 的前 60 个字符**。而“把 gate 加进 extraResources”这条补丁的写法是
「**锚点原样保留 + 在下面追加一行**」——于是这个标记恰好就是锚点本身：锚点在文件里 → 判定“已打过” →
**整条补丁被静默跳过**，报告里只写「已打过（跳过）」，看不出任何异常。
0.1.6 时那行配置的缩进/上下文不同、前缀没撞上，所以一直是好的；0.1.7 恰好撞上。

修复：
1. `patch()` 的默认标记改为取**新增部分**（`replacement` 去掉前缀锚点后的文本），
   新增部分过短时退化为整段 `replacement`，从根上消除这类“标记=锚点”的自噬；
2. `verify-upstream-patches.mjs` 增加硬断言：打包配置里必须能看到 `../resources/gate`，
   且 `apps/desktop/resources/gate/` 下 6 个页面/补丁层文件都在（缺一个就拒绝出包）；
3. `scripts/p123-install-cycle.mjs` 增加安装后**落盘资源核对**（gate 页面 / lo / runtime / app.asar），
   以后再缺文件在安装测试阶段就会红，而不是等学生启动才发现。

已用反证验证守卫有效：把配置里的 gate 条目临时删掉 → 校验立刻失败。

### 启动窗口不可见事故与 0.1.7-alpha.2.2 已发布（2026-09-24）

`verify-upstream-patches.mjs` 增加 `window.show()` 硬断言，防止再次退回隐藏窗口。
