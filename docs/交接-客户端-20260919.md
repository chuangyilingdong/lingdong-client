## 二、仓库结构与上游 pin

```
deploy/desktop/
  rebrand-client.mjs        品牌：产品名/文案/字标/图标/窗口标题
  apply-client-gate.mjs     把 client-patch 接进上游检出（6 处锚点，幂等）
  publish-client.sh         传安装包 + 置回清单 + 核验
  assets/lingdong-ai-logo.png   字标源图（生成 gate/logo.png 与应用图标用）
  client-patch/
    platform-gate.ts        登录门主进程逻辑（账号 → client-context → 写补丁/密钥 → 放行）
    lingdong.patch.yml      补丁层：模型只走我们网关 + 关掉成人入口
    gate/{login,waiting,loading}.html + mascot.png + logo.png + app-icon-1024.png
scripts/
  p116-client-gate-ui.mjs   门三页的界面守卫
  electron-mirror.mjs       离线出包用的本地 Electron 镜像
upstream/                   gitignore：上游检出 + 构建缓存 + 官方 SHASUMS
  dsh-harness/              钉在 ddefc45（tag dsh-v0.1.6-alpha.2）
  electron-mirror/v44.0.0/SHASUMS256.txt
```

⚠️ `upstream/dsh-harness/node_modules` 与 `.desktop-build*`（含解出来的 Electron、烤好的
dsh 运行时、主运行时 node/python/pnpm）**是这份缓存让本机不需要联网就能出包**，
**不要删**（这台机器上 npm registry 是打不通的，删了装不回来）。

## 三、出包（Windows）

```bash
node deploy/desktop/rebrand-client.mjs --checkout upstream/dsh-harness   # ① 先品牌
node deploy/desktop/apply-client-gate.mjs --checkout upstream/dsh-harness # ② 再登录门
cd upstream/dsh-harness
export PATH="/c/Program Files/nodejs:/c/WINDOWS/system32:$PATH"
export LINGDONG_BUILD_ROOT=.desktop-build2
pnpm --filter @deepseek-ai/dsh-desktop run package:win:x64:unsigned        # 约 30 分钟
```
产物：`upstream/dsh-harness/apps/desktop/.desktop-build2/targets/win-x64/unsigned-artifacts/lingdong-client-*.exe`

发布：`bash deploy/desktop/publish-client.sh <安装包路径>`（传上去 → 置回清单 → 从服务器侧核验；
如需 SSH 身份，用的是 `~/.ssh/ai_kids_platform_ecs_temp_ed25519`）。

### 打不通 GitHub release 资产时（本机就是这种情况）

`prepare:runtime` 要 `@electron/get` 取 **Electron 运行时**并校验 `SHASUMS256.txt`，
而它**每次都直连 GitHub、不走缓存**：

```bash
# 1) 从能上外网的机器（我们用的是生产服务器）取官方校验文件
ssh <服务器> 'curl -sL https://github.com/electron/electron/releases/download/v44.0.0/SHASUMS256.txt' \
  > upstream/electron-mirror/v44.0.0/SHASUMS256.txt
# 2) 与本机已缓存的那份 zip 对 sha256 —— **一致才用**（这是真的完整性校验，不是绕过校验）
sha256sum "$LOCALAPPDATA/electron/Cache/*/electron-v44.0.0-win32-x64.zip"
# 3) 起本地镜像并按镜像出包
node scripts/electron-mirror.mjs 18920 &
cd upstream/dsh-harness && ELECTRON_MIRROR=http://127.0.0.1:18920/ pnpm --filter @deepseek-ai/dsh-desktop run package:win:x64:unsigned
```

## 四、本地把客户端跑起来（不用出包）

```bash
export ELECTRON_OVERRIDE_DIST_PATH=<检出>/apps/desktop/.desktop-build2/targets/win-x64/electron
export LINGDONG_API_BASE=http://127.0.0.1:18910     # 平台仓库 scripts/dev-bench.mjs 的端口
export DSH_HOME=<隔离目录>                          # ⚠️ 别用真的 ~/.dsh
export DSH_DESKTOP_OPEN_DEVTOOLS=0
cd upstream/dsh-harness && pnpm --filter @deepseek-ai/dsh-desktop run start   # --skip-build
```

驱动它（没有 Playwright 的 Electron 支持好用，直接说 CDP 协议最稳）：

- 客户端渲染进程的调试端口是 **9222**（`dev.ts` 里写死）。
- `curl http://127.0.0.1:9222/json/list` 看页面；`ws://…/devtools/page/<id>` 上直接发 CDP。
- **写进 React 受控输入框只能用 `Input.insertText`**（直接改 `.value` / `innerText` 它不认），
  发消息用 `Input.dispatchKeyEvent` 的 Enter。
- Playwright 的 `connectOverCDP` 接 Electron 会**超时**，别用。
- 「选择工作区」点的是原生目录选择器（CDP 驱动不了）：直接预置
  `$DSH_HOME/storages/workspace.json`（形状 `{unit, global:{workspaceIds:[…]},
  tables:{workspaces:{<id>:{path,title,sessionIds,createdAt,updatedAt}}}}`）再**重启**客户端
  （storage 由宿主进程缓存在内存里，改文件不热生效）。

## 五、不许破的口径（客户端侧）

1. **模型只走平台网关**：补丁层禁官方直连、默认模型指 `platform-gateway`，不许出现别的上游地址。
2. **过门之后要 `resetHost()`**（`main.ts` 里 `runLingdongGate(createMainWindow, isQuitting, () => backend.stop())`）：
   宿主可能在别的路径（更新/恢复、策略检查）先起来，而**宿主进程的环境是 spawn 那一刻定下来的** ——
   密钥事后写 `process.env` 到不了它那一侧。停一次，让后面的 `reconcileBackend()` 用新环境重起。
3. **补丁层走宿主的 `patchFiles`**，不许写 profile 的 `cordis.patch.yml`
   （桌面宿主显式传空数组，那个文件**永远不会被读**）。
4. **登录门必须在 `automaticCheck()` 之前**（更新/恢复流程会在它里面起宿主）。
5. **品牌改常量而不是只传环境变量**：`DSH_CLIENT_TITLE` 被 `assertClientBuildEnvironment`
   **断言**，只传 env 会让构建直接失败。
6. **门页面的 CSP 要放开 `img-src file:`**：`default-src 'none'` 下图片被挡是**静默**的
   （页面照常渲染、只是那块空白）。
7. **改 `apply-client-gate.mjs` 的补丁时，幂等 marker 要用新特征串**，并且**改了签名要有升级路径**
   （原地替换旧行）—— 只按锚点插入会留下旧行，**登录门弹两次**。

## 六、这一路踩过的坑（客户端相关的）

1. ⭐ **宿主（dsh）与登录门的顺序**：这是客户端能不能调通网关的**唯一门槛**，见口径 2。
   上一轮曾误判成「宿主必定起在门之前」，后来读代码发现 `backend.start()` 就在门后面；
   真正的修法是"过门后明确停一次"，**真客户端实测通过**。
2. ⭐ **字标是矢量稿**：上游那幅 `deepseek HARNESS` 的字母是 SVG path，**字符串替换一处也改不到** ——
   要改的是"字标产地"三个文件（`web/boot-page.ts`、locale 的 `brand.localBuild`、
   `ui-brand-official/Brand.tsx` 整份覆盖）。官方构建档（`DSH_CLIENT_BUILD_PROFILE=official`）
   走的是 `Brand.tsx`。
3. **应用图标是三个文件**（`icon-windows.png` / `icon-macos.png` / `icon.png`），要一起换；
   原来靠手工复制、漏过一次 —— 现在 `rebrand-client.mjs` 自动铺。
4. **设计稿里烘着文案**：从参考图裁素材（`gate/mascot.png` 就是这么来的）会把它自己的文字一起带进去；
   正解是先抹平再裁（那块是平滑红渐变，取上下两条干净锚线做纵向插值就接得上）。
5. **dev 模式跑着的客户端会占住打包要删的 `electron/` 目录** → 打包报 `EPERM`。
   打包前先把 electron 进程全收掉（那次有 6 个）。
6. `prepare:dsh` 阶段的 pnpm 偶发崩一次（`PostQueuedCompletionStatus … 句柄无效`），**重跑一次就过**。
7. **Git Bash 的 GNU tar 把 `E:\…` 当远程主机**；`PATH` 里要放 Windows 的 bsdtar（`System32/tar.exe`），
   且目录要写成 MSYS 形式（`/e/...`）。
8. **PATH 里的 `node` 可能是 v16**（微信开发者工具那份）：打包前把 `C:\Program Files\nodejs` 放到最前。
9. **上游默认带的第三方插件会让客户端启动即失败**（`dsh-dream-skin` 导入失败被判致命），
   必须在打包前禁掉（客户端自带「禁用第三方插件并重启」的恢复按钮可以借它一次性关掉）。
