# 给平台：课堂发送计数幂等与全局提示词接入（2026-11-01）

## 一、发送次数误计问题

### 现场数据

- 账号：`xueshengpeixun1-1`
- 课堂：`csession_a5330d4b4c7e4bba8eff`
- 课时上限：7
- 客户端显示：2/7
- 数据库 `session_students.vibecoding_sends`：9
- 首次 429：`2026-11-01T12:10:30Z`
- 该课堂从 `11:53:01Z` 到 `12:10:22Z` 有 146 次成功的内部模型请求
- 客户端错误 requestId：`d92763fc-0329-4dca-8c9b-4bb8104ad47b`
- 平台错误码：`SEND_QUOTA_EXCEEDED`

这不是学生真实按了 7 次发送。当前服务端通过对话历史里的 `user` 消息推断发送次数，Agent 工具轮
的注入消息仍有机会被误认为新发送。

### 客户端已配合的改动

客户端从现在开始会给每次真实用户发送派生出的所有模型请求携带稳定请求头：

```http
x-zcode-send-id: <turnId>
```

语义：

1. 同一个用户发送产生的工具轮、压缩、标题 sidecar、子代理、SSE 重试、网络重连均复用同一个值。
2. 用户下一次点击发送才会产生新值。
3. 没有 `turnId` 的后台模型请求不会伪造该头。

### 平台需要改什么

1. 网关读取 `x-zcode-send-id`。
2. 按 `(class_session_id, student_id, send_id)` 做唯一幂等计数，不再按 user 消息条数推断。
3. 首次见到新 sendId 时在事务中检查 limit 并 `used + 1`；重复 sendId 只校验权限，不再增加次数。
4. 同 sendId 的并发请求必须由数据库唯一约束收敛，不能先查后写。
5. `client-context.sends` 继续返回 `{ limit, used, remaining }`，其中 `used = min(count, limit)`。
6. 超限仍返回 HTTP 429 + `SEND_QUOTA_EXCEEDED`，不要新增错误码。

建议最小表结构：

```sql
CREATE TABLE session_vibecoding_sends (
  session_id VARCHAR(64) NOT NULL,
  student_id VARCHAR(64) NOT NULL,
  send_id VARCHAR(128) NOT NULL,
  first_seen_at DATETIME NOT NULL,
  PRIMARY KEY (session_id, student_id, send_id)
);
```

计数以该表 distinct 行数为准。旧的 `session_students.vibecoding_sends` 可以作为缓存/兼容字段，
但不能再是事实源；迁移完成后应重建或校正。

### 旧客户端兼容

- 没有 `x-zcode-send-id` 的请求不能按新逻辑加次。
- 需要保留旧客户端兼容路径时，必须按客户端版本隔离；不要把新包和旧包的计数混写。
- 新版本达到最低版本门槛后，可删除消息内容启发式。

### 数据修复

平台发布后，这一场课堂需要按实际真实发送次数校正。当前客户端本地记录是 2，数据库原始值是 9，
对外封顶成 7。建议平台核对学生实际发送后将该场 `vibecoding_sends` 回写为正确值，并补齐/清理
sendId 幂等记录。

### 平台验收

1. 同一个 sendId 连续 100 次工具模型请求，计数只加 1。
2. 同一 sendId 的断线重试、密钥过期重试、并发请求不重复加次。
3. 新 sendId 加 1。
4. 第 7 次成功后，`client-context` 返回 `used=7, remaining=0`。
5. 第 8 次发送返回 429 `SEND_QUOTA_EXCEEDED`。
6. 旧客户端缺少 sendId 时不会因工具轮增加计数。

## 二、后台可配置全局系统提示词

### 客户端字段契约

`GET /api/student/runtime/client-context` 增加两个可选字段：

```json
{
  "globalSystemPrompt": "平台规定的全局约束",
  "globalSystemPromptRevision": "2026-11-01T10:00:00Z"
}
```

约束：

- `globalSystemPrompt`：字符串，UTF-8 最大 32 KiB；空字符串/缺失 = 不启用。
- `globalSystemPromptRevision`：任意短字符串，只用于诊断日志，绝不进入模型上下文。
- 不要在字段里放密钥、token、手机号等敏感数据。
- 教师备课上下文可以不带这两个字段；如果带，客户端也会按同一规则保存。

### 客户端行为

1. Main 按 workspace identity 原子写入独立提示词文件。
2. 新建任务/新 runtime 时，Agent 读取该文件，把提示词作为独立 system section 追加。
3. 平台提示词不会替换内置 Agent 安全边界，也不会显示给用户编辑。
4. 主 Agent 与子 Agent 都生效。
5. 超 32 KiB、读取失败或空内容：忽略整段并记录不含正文的告警。
6. 已初始化 ContextBuilder 的当前会话保持原提示词，避免修改历史 system 上下文；新任务、新 runtime
   或重登后使用新版本。

### 平台验收

1. 下发提示词后新建任务，模型首轮 system prompt 包含该内容。
2. 更新 revision 和正文后，新任务使用新正文。
3. 清空字段后，新任务不再包含旧提示词。
4. 超过 32 KiB 时不出现半截提示词。
5. 客户端日志不出现提示词正文。
