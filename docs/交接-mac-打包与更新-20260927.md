# 交接：macOS Apple 芯片打包与更新（2026-09-27）

## 结论

- 客户端代码已支持 `mac-arm64`：
  - 放行上游 macOS 打包路径；
  - DMG/ZIP 产物改成灵动ai品牌名；
  - 启动更新器可读取平台清单里的 `files['mac-arm64']`，下载并校验 DMG；
  - macOS 更新不静默替换应用，而是打开 DMG 让用户拖入“应用程序”替换后重开。
- 当前工作机是 Windows x64，上游明确禁止非 macOS 主机构建 `mac-arm64`，所以**还没产出真实 DMG**。
- 已准备好 `scripts/build-mac-arm64.sh` 和扩展后的 `deploy/desktop/publish-client.sh`。
- 尚未发布，也没有改平台仓库。

## 构建 Mac 包的硬要求

1. **Apple Silicon macOS 构建机**。当前上游 `package-target.ts` 会检查：
   - `process.platform === 'darwin'`
   - `process.arch === 'arm64'`
2. Node.js >= 22、pnpm、Xcode Command Line Tools。
3. 正式分发包还需要 Apple Developer Program 下的：
   - `Developer ID Application` 证书（`.p12`）；
   - `DSH_DESKTOP_MACOS_SIGNING_IDENTITY`、`DSH_DESKTOP_MACOS_TEAM_ID`；
   - 一套 notarization 凭据：App Store Connect API Key，或 Apple ID app-specific password。
4. macOS 正式包必须签名并公证；未签名包只能本机验收，学生下载后会被 Gatekeeper 拦截。

## 客户端已准备好的命令

```bash
# 正式签名 + 公证包
bash scripts/build-mac-arm64.sh
# 产物：apps/desktop/.desktop-build/targets/mac-arm64/artifacts/lingdong-client-<版本>-mac-arm64.dmg

# 无证书本机验收包（不能外发）
bash scripts/build-mac-arm64.sh --unsigned
# 产物：.../mac-arm64/unsigned-artifacts/lingdong-client-<版本>-mac-arm64-unsigned.dmg

# 发布时 Windows 与 Mac 必须同版本，一次传两个包
bash deploy/desktop/publish-client.sh \
  <lingdong-client-<版本>-win-x64.exe> \
  <lingdong-client-<版本>-mac-arm64.dmg>
```

## 平台端需要配合的事项

### 现在就必须确认

1. **上传/下载入口**：平台后台已经能接收 `lingdong-client-<版本>-mac-arm64.dmg`，官网 `/download` 也已读取 `files['mac-arm64']`；需要确认生产环境的 Nginx/上传大小限制能容纳 Mac DMG。
2. **双端同版本**：当前 `manifest.json` 只有一个顶层 `version`。这次发布应把 Windows 与 Mac 同版本一次发布；客户端发布脚本已阻止单端版本漂移。
3. **后台展示**：`clientUpdateManifest.js` 的读取视图目前只解析 `files['win-x64']`，后台“客户端更新”页看不到 Mac 文件名/大小/SHA256。即使不阻塞发布，也应补上 `mac-arm64` 展示与存在性提示。
4. **Apple 凭据**：签名/公证凭据只应放在 Mac 构建机或 CI secrets，不要写进平台仓库、客户端仓库或发布脚本。

### 若要做到 Win/Mac 独立发版

需要一个契约小改动：

- 给 `manifest.files[target]` 增加独立 `version`；
- 客户端按 `files[target].version ?? manifest.version` 判断更新；
- 平台后台分别展示两个平台的版本、文件、大小和 SHA256；
- 发布脚本允许单平台发布，但仍保留“文件 + 大小 + SHA256 + 版本”四项原子写入。

在平台完成这个字段前，不要单独发布 Mac，否则旧 Windows 客户端会因为顶层 `version` 提前升高而误判更新。

### 若要做到 macOS 完全自动更新

当前实现是“下载并打开 DMG，用户替换应用”，不是静默替换。要做到 Windows 那种自动更新，可按标准 Electron macOS 流程另做一条：

- 产物使用签名后的 `.zip`、`.zip.blockmap` 和 `latest-mac.yml`；
- 平台提供稳定的 HTTPS 更新源；
- 客户端接入 `electron-updater` 的 macOS 流程，且新旧版本必须保持同一 Team ID、签名和公证有效。

这需要平台端增加 ZIP/blockmap 托管与上传类型支持，不能直接把现有 DMG 当静默安装器使用。
