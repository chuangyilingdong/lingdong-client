# 客户端启动更新门与待安装恢复

## 背景

桌面客户端存在两个相互关联的更新体验问题：

1. 已下载但尚未安装的更新，其“待安装”状态在登录门之后才恢复，导致更新弹窗只能等用户登录后出现。
2. 从持久化待安装状态恢复出来的“已准备就绪”，并不包含 `electron-updater` 当前进程的真实安装上下文。用户点击“重启以更新”时，如果未开启自动下载，只会回退到“发现更新”，看起来像按钮没有反应。

自动更新状态的所有者是 desktop main 进程中的 `autoUpdater` 模块。renderer 只投影状态并发送命令，不持有第二份待安装事实。

## 启动顺序

```text
app ready
  -> 读取主进程设置
  -> hydrate pending update（恢复待安装状态）
  -> init autoUpdater / 启动一次更新检查
  -> waitForStartupUpdateDecision
       ├─ update-available / download-progress / update-downloaded：先显示更新窗
       └─ 检查确认无更新或失败收口：进入登录门
```

不变量：

- 待安装恢复必须先于启动更新门和登录门。
- 第一次更新检查未收口前，不能用初始 `idle` 快照提前放行登录门。
- 更新检查失败、超时或明确无更新时必须放行登录门，避免把启动永久卡死。
- 一旦进入有更新的等待阶段，启动门必须等更新窗关闭后再继续。
- 更新窗启动前必须注册自身的只读状态查询、自动下载设置和桌面活动查询 IPC；这些 handler 之后可幂等重挂，不能依赖登录完成后的完整平台初始化。

## 待安装恢复与显式重启

`pendingPostUpdateReleaseNotes` 只证明用户曾下载过某个未来版本，不代表当前进程已经具备可安装上下文。

- 启动时若恢复出版本高于当前应用的待安装状态，应先显示“已准备就绪”，不能等到登录后再显示。
- 更新检查确认远端仍是同一版本或更低版本时，保留该恢复态，不用一次后台检查覆盖用户看到的状态。
- 远端已是更高版本时，丢弃旧的恢复态，按更高版本进入“发现更新”流程。
- 用户点击“重启以更新”时，如果当前是恢复态，必须无条件重新下载/重新 stage 当前版本；是否开启自动下载只影响后台行为，不能阻止显式安装命令。
- 重新下载完成并收到真实的 `update-downloaded` 后，才允许进入 `quitAndInstall`。
- 重新下载失败或用户取消下载时，清除“下载完成后自动安装”的意图，回到可重试状态，不能让按钮永久 pending。

## 验收

1. 存在持久化待安装版本时，启动后先出现更新窗，登录窗不得抢先出现。
2. 点击更新窗“稍后”关闭后，登录门才继续。
3. 恢复态点击“重启以更新”时，即使自动下载开关为关闭，也必须重新下载并在下载完成后进入安装。
4. 无更新、检查失败或检查超时时，登录门仍会继续，不能永久阻塞启动。

## 仅启动阶段处理更新（2026-11-03）

更新检查、下载和安装都只属于启动更新门。主窗口一旦放行，本次运行不再处理任何更新动作。

```text
app ready
  -> hydrate pending update
  -> init autoUpdater（只启动一次检查）
  -> waitForStartupUpdateDecision
       ├─ 有更新：更新窗内允许下载/安装，关闭更新窗后封存
       └─ 无更新/失败/超时：直接封存
  -> sealAutoUpdaterForCurrentRun
  -> 登录门 / 主窗口
```

不变量：

- 运行期不设置更新轮询定时器。
- 启动更新门结束后，主进程封存更新器；运行期手动检查、频道刷新、下载和安装命令必须 fail-closed。
- 封存后的菜单状态为 `idle + enabled=false`，更新入口显示“更新仅在启动时检查”，不允许用户误以为可以立即检查。
- 启动检查超时后迟到的结果不得再触发下载、更新窗或安装；待安装缓存留到下一次启动恢复。
- `autoInstallOnAppQuit` 必须关闭，普通退出不能绕过显式安装入口自动安装缓存更新。
- 每次显式安装前重新校验已下载安装包的 SHA-256（或可用的 SHA-512）。校验失败时删除损坏文件、清除待安装状态并报错，绝不能启动 NSIS 安装器。
- 更新器状态的所有者仍是 desktop main 的 `autoUpdater` 模块；renderer 不新增运行期更新状态。

验收：

1. 启动检查完成后，主窗口中的“检查更新”入口处于禁用状态，文案说明更新只在启动时检查。
2. 主窗口放行后调用检查、下载或安装命令不会发起网络请求，也不会启动安装器。
3. 等待超过原轮询周期后仍不会发生第二次更新检查。
4. 启动阶段的下载完成后，若安装器文件被篡改或损坏，安装被拒绝并回到可继续使用的状态。
5. 普通退出不会自动安装已下载更新；下一次启动仍可恢复待安装状态。
