# 客户端 ↔ 平台 接口契约（2026-09-19）

> **这份文档是两边唯一的接口依据。** 客户端仓库与平台仓库各自独立开发，
> **任何一端要改这里的形状/语义，必须两个仓库同时改，并在本文件里改一行历史**（见文末「改契约的规矩」）。
> 平台侧这些行为有守卫钉着（`p117` / `p118` / `p119`），客户端侧是 `p116`。

## 一、谁拥有什么

| 东西 | 归谁 | 说明 |
|---|---|---|
| 登录门、登录页/等待页、品牌、补丁层、安装包 | **客户端仓库** | `deploy/desktop/**`、`upstream/` |
| 账号与课堂（谁在哪个课堂、老师开没开课） | **平台仓库** | 客户端只问「我现在能不能进」 |
| 运行时密钥的签发与校验、网关门禁、用量记账 | **平台仓库** | 客户端不自己发密钥、不算账 |
| 发送次数上限 | **平台仓库** | 客户端只把 429 的 `error.message` 原样显示给学生 |
| 预设提示词、剩余次数 | **平台仓库下发**（`client-context`），**客户端负责显示** | 显示与交互在客户端 |
| 作品落库（`vibecoding_submissions`） | **平台仓库** | 客户端负责把字节传上来 |
| 安装包托管 + 下载清单 | **平台仓库**（`/srv/ai-kids-platform/downloads/`） | 客户端负责**发布**（`publish-client.sh`） |
| 官网「打开创作客户端」入口 | **平台仓库** | 深链 `lingdong://open` 由客户端注册 |

## 二、客户端会用到的接口

基线地址：`LINGDONG_API_BASE`（客户端里默认 `https://iicili.cyou`，本机验证时指到本地平台）。

### ① 登录
```http
POST /api/auth/login
{ "login": "student-1", "password": "study123" }
→ 200 { "data": { "token": "...", "expiresAt": "...", "user": { "id", "orgId", "role", "displayName", "login" } } }
```
失败：`401`，`error.message` 是给人看的中文。客户端把 token 存在 `userData/lingdong-session.json`。

### ② 进门：这节课的上下文（**唯一的密钥来源**）
```http
GET /api/student/runtime/client-context        Authorization: Bearer <上面的 token>
→ 200 {
    "classroom": { "id", "lessonId", "title" } | null,
    "gateway":   { "baseUrl": "https://…/api/gateway/v1", "key": "rt1.<base64url>.<签名>" },
    "presets":   [ { "title": "…", "text": "…" } ],
    "sends":     { "limit": 3 | null, "used": 1, "remaining": 2 | null },
    "message":   "老师还没有开始上课"        // 仅当 classroom=null
  }
```
- **`classroom === null` 就是「老师没点开始上课」**：客户端此时**不许**进创作环境（没有密钥，进去了也调不动网关）。
- `gateway.key` 是**运行时密钥**：绑了机构/学生/课堂/课时，TTL 6 小时；**网关每次调用都重新过门禁**
  （课堂还在进行 + 学生还在名单里），老师结束课堂后立刻失效。
- `sends.limit === null` 表示这节课没设上限（不填 = 不拦）；`used` 已封顶到 `limit`。
- 平台侧配置缺失时 `409 RUNTIME_GATEWAY_UNCONFIGURED`（**这是平台没配好，不是学生的问题**）。

### ③ 模型调用（OpenAI 方言，**客户端唯一的模型出口**）
```http
POST <gateway.baseUrl>/chat/completions        Authorization: Bearer <gateway.key>
{ "model": "deepseek-flash", "messages": [...], "stream": true, ... }
```
- 就是 OpenAI 的 `chat/completions`（`model` / `messages` / `stream` / `tools` 都照原样转）。
  补丁层里那两个模型名（`deepseek-flash` / `deepseek-pro`）**只是给学生看的槽位名**，
  平台按自己渠道的清单解析，认不出就用该渠道默认模型。
- ⚠️ 请求体上限 **24MB**（`RUNTIME_GATEWAY_BODY_LIMIT`）。
- **超发送次数**：`429`
  ```json
  { "error": { "message": "这节课的发送次数用完了（共 3 次）。…",
               "type": "send_limit_exceeded", "code": "SEND_LIMIT_EXCEEDED" } }
  ```
  客户端把 `error.message` **原样**显示给学生（那句话是给学生看的中文）。
- 密钥问题：`401` `error.code` = `RUNTIME_KEY_INVALID` / `RUNTIME_KEY_EXPIRED`；
  课堂已结束：`403`（`RUNTIME_NO_ACTIVE_CLASSROOM` 一类）——**这几种都要引导学生回去重新登录/等老师开课**。

### ④ 交作品（学生在**自己电脑上**做出来的东西）
```http
POST /api/student/runtime/submit-upload        Authorization: Bearer <学生 token>
{
  "name": "index.html",              // 主产物，必须在 files 里
  "title": "我的自我介绍网页",        // 可省略（省略时用课堂名）
  "description": "…",                // 可省略
  "copyrightConfirmed": true,        // 必须显式确认（提交即授权平台在作品广场展示）
  "files": [
    { "name": "index.html", "content": "<!doctype html>…", "binary": false },
    { "name": "cat.png",    "content": "<base64>",         "binary": true  }
  ]
}
→ 200 { "id", "entryFile", "warnings": [...], "missing": [...], ... }
```
- `binary: true` 时 `content` 是 **base64**；`binary: false` 时是**文本原文**（UTF-8）。
- 上限：**≤60 个文件**、解回来**总量 ≤16MB**、整个请求体 ≤24MB（`index.js` 按路径开的额度）。
- 支持的类型：网页（`.html`）、PPT（`.pptx`）、Word（`.docx`）、Excel（`.xlsx`）作主产物；
  图片（png/jpg/gif/webp）可作被引用的素材随作品一起交。
- 错误（都是 `400`，位置在 `error.code`）：
  `WORK_COPYRIGHT_CONFIRMATION_REQUIRED`、`RUNTIME_UPLOAD_NAME_REQUIRED`、`RUNTIME_UPLOAD_EMPTY`、
  `INVALID_ARTIFACT_NAME`（**文件名不许带路径**，是拒绝不是改名）、`RUNTIME_UPLOAD_DUPLICATE_NAME`、
  `RUNTIME_UPLOAD_ENTRY_MISSING`、`RUNTIME_UPLOAD_TOO_MANY_FILES`、`RUNTIME_UPLOAD_TOO_LARGE`、
  `VIBECODING_ARTIFACT_NOT_SUBMITTABLE`；太大到超过 24MB 时是框架的 `413 PAYLOAD_TOO_LARGE`。
- 返回里的 `warnings` / `missing` **要显示给学生**：提交成功但作品缺了东西，比提交失败更糟。

### ⑥ 查自己交过什么（客户端做「交作品」那一屏时会用到）
```http
GET /api/student/works?page=1&limit=20        Authorization: Bearer <学生 token>
→ 200 { "items": [ … ], "summary": { "total", "published", "withFeedback" }, "page", "limit" }
```
- 学生自己交过的作品：**画布作品 + VibeCoding 提交两类合并**后按提交时间倒序。每条大致有
  `id / title / status / isPublic / teacherComment / submittedAt / source(CANVAS|VIBECODING) /
  entryFile / submissionRound / seriesTitle / lessonTitle`。
- ⚠️ `total` 是**两类相加**的口径，分页也是合并后分的 —— 客户端别自己按 `source` 过滤再当成总数。
- 需要作品内容快照时加 `includeSnapshot=true`（体积大，只在打开某一件时用）。
- 这样客户端「交完作品」就能立刻回显「我交过什么」，不必自己存一份本地列表。

### ⑦ 下载清单（官网下载页读它，客户端发布时写它）
```http
GET /downloads/manifest.json
{ "version": "0.1.6-alpha.2", "channel": "internal-beta", "updatedAt": "…", "note": "…",
  "files": { "win-x64": { "name": "lingdong-client-…-win-x64.exe", "size": 308138555, "sha256": "…" },
             "mac-arm64": null } }
```
安装包实体放在**发布目录之外**的 `/srv/ai-kids-platform/downloads/`，每次发布换代都不会冲掉；
`files['win-x64'] = null` 表示**暂时不对外开放下载**（客户端跑不通时就该是 null）。

## 三、两边都必须遵守的口径

1. **客户端的模型调用只走平台网关**：补丁层禁掉官方直连渠道（`llm-deepseek`），
   默认模型指到 `platform-gateway`。客户端不许出现任何别的上游地址。
2. **密钥只来自 `client-context`**；没在上的课不发密钥 —— 这是「老师点了开始上课才能进」的**服务端兜底**，
   客户端被改也拿不到。
3. **发送次数只数学生自己按的那一下**：dsh 每轮会注入 user 消息（运行时上下文快照、
   `<system-reminder>` 指令块），**都不算**。客户端不需要做任何配合，但**别试图自己算次数**
   （客户端报数一概不信，平台只认网关看到的对话历史）。
4. **超限的提示语是平台给的**（`error.message`），客户端**原样显示**，不要自己编一句。
5. **品牌合规**（上游 `BRAND_GUIDELINES.zh.md`）：MIT 允许再分发与换牌；描述可写「基于 DSH 构建」；
   但**项目名不得用 "DeepSeek Harness" 全称**、不得暗示官方背书。
6. **网页侧不再有创作环境**：官网只负责把学生送到客户端（`lingdong://open` + 下载页），
   不许再出现 `student/runtime/launch|deliverables|submit`（平台侧 `p117` 钉着）。

## 四、本地联调（客户端怎么在没有生产账号的情况下验）

平台仓库里有验证台脚本 **`scripts/dev-bench.mjs`**：起一个**临时库**的整套平台
（种子数据 + 一节 VIBECODING 课堂 + 网关指回自己 + `AI_PROVIDER=local-mock`），
打印端口与账号（`student-1 / study123`），信息写进 `.tmp/bench-info.json`。

```bash
# 平台仓库里
node scripts/dev-bench.mjs                 # 默认端口 18910
# 客户端这边
export LINGDONG_API_BASE=http://127.0.0.1:18910
export DSH_HOME=<隔离目录>
pnpm --filter @deepseek-ai/dsh-desktop run start
```
进得去之后发一条消息，去平台库里看 `usage_records`（应为 `SUCCESS`）与
`session_students.vibecoding_sends`（应恰好 +1）—— 这就是客户端「真的通了」的判据。

## 五、改契约的规矩

1. 形状/语义的改动**必须两个仓库同时改**，先改平台（服务端）再改客户端，或反过来都行，
   但**同一天内两边都要落到 `main` 分支**。
2. 平台侧改动要跟着更新对应的守卫（`p117`/`p118`/`p119`）—— 那些守卫就是这些口径的可执行版本。
